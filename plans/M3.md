# M3 - Map editor plugin: tile painting

## Where we are (branch feature/map-editor-plugin)

IMPLEMENTED (port option 1 chosen by the owner): suite green 518/518, smoke
OK, golden OK, zero SCRIPT ERRORs. The interactive painting layer is
user-in-the-loop verified (remote machine): the acceptance gate stays open
until then.

## Port (option 1) — done

mirror_tiles.gd is now `@tool extends TileMapLayer` (each layer mirrors
itself): same changed-snapshot diff pattern, single-layer snapshot keys
"x:y", and the mirror math lives in tile_brush_logic.gd (mirrored_cell),
shared with the plugin's brush. test_mirror_tiles.gd rewritten against the
new API — involution, reversibility, even/odd values, and diffing all kept,
plus end-to-end sync and set_mirrored_cell tests.

## Post-verification fixes (user-remote testing, 2026-11-21)

1. **Undo was broken by invalid Callables**: stroke undo queued
   `restore_cell_state` (a TileBrushLogic static) against the TileMapLayer —
   a Callable to a method the object lacks is invalid, and UndoRedo errored
   "!p_callable.is_valid()" per cell instead of recording undo. Stroke undo
   now replays with real TileMapLayer methods (set_cell/erase_cell from the
   captured pre-state).
2. **Tile picker shows preview icons** — 96px (4x, user-requested size),
   aspect kept, nearest-neighbor, and always scaled to fit (UP or DOWN — an
   8px ground cell is invisible at native size). Engine quirks:
   OptionButton.add_item takes an int id in 4.7.2 (icons go via
   get_popup().set_item_icon); GradientTexture2D and placeholder textures
   have no readable pixels headless — tests use Image + ImageTexture;
   TileSetAtlasSource.texture_region_size defaults to 16x16, so test sources
   must declare it explicitly (real map sources already do).
3. **Block-size dropdown**: powers of two in cells up to the full map tile
   (ground 1/2/4/8, trees 1/2/3, walls 1). Full tile (default) keeps the
   snapped 64px behavior; smaller sizes anchor an n x n block at the clicked
   cell for detail work.

## Runtime contract learned during implementation

- pathfind/navigation.gd reads the WALLS layer's SOURCE ID as the wall's
  team (0 = blue, else red) — the dock tile picker therefore lists
  (source_id, atlas) pairs, not just atlas coords.
- Cell sizes differ per layer: ground TileSet 8px, walls 64px (must equal
  tile_size — validator + paint guard), trees 24px. One click paints a
  whole map tile (64px) worth of layer cells: 8x8 ground, 1x1 walls, 3x3
  trees.
- trees have no GDScript consumer (only base_map's @onready; occlusion is
  engine-side) — still a contract layer, still brushable.

## Where this fits

"Next phases" Phase 4 from M1.md: polish on top of map/tool/mirror_tiles.gd.
Users currently paint in Godot's built-in TileMap editor and mirroring
happens automatically; this adds explicit, dock-driven brushes so the three
contract layers are one click each — and adds the guards the validator
already demands (walls cell size).

## What exists (verified 2026-11)

- `map/tool/mirror_tiles.gd` (@tool, extends TileMap) — auto-mirrors edits:
  snapshots cells, diffs them on `changed`, writes/erases the mirrored
  coordinate via `set_mirrored_cell`. Godot-3-style multi-layer TileMap API
  (get_layers_count / set_cell(layer, ...)).
- The runtime contract (map_validator._check_tiles + base_map.gd @onready)
  requires three **TileMapLayer** nodes: tiles/ground/Ground,
  tiles/walls/Walls, tiles/trees/Trees. Shipping maps run an (8, 8) ground
  cell size against tile_size 64 (legal — walls is the only layer the
  validator size-checks, because navigation.gd grids walls by tile_size).
- No .tscn currently uses mirror_tiles.gd — it is a tool-class surface with
  its own headless suite (tests/unit/test_mirror_tiles.gd, registered in
  tests/run_tests.gd) covering involution, reversibility, even/odd sizes,
  and cell diffing.
- TileSet resources live with the maps (map/maps/*.tscn carry the three
  layers' tile_sets).

## DECISION REQUIRED before implementation

mirror_tiles.gd extends TileMap (multi-layer API) but the contract layers
are TileMapLayer nodes. Pick ONE:
1. Port mirror_tiles.gd to a TileMapLayer-oriented helper (recommended):
   brush writes to a target TileMapLayer and its mirrored coordinate; the
   mirror math moves to/refactors into the pure helper this plan tests.
   Existing test_mirror_tiles.gd cases are rewritten against the new API —
   the mirror invariants (involution, reversibility, diffing) must survive.
2. Keep TileMap and drive the three TileMapLayers from a separate node —
   two mirror implementations, not acceptable long-term.
Option 1 is recommended; do not start implementation before the owner picks.

## Design sketch

1. **Pure logic first** (`tile_brush_logic.gd`, RefCounted):
   - `layer_for_brush(map_root, brush) -> TileMapLayer` — ground/walls/trees
     -> the three required paths; null-safe with a reason string for the
     dock error (missing layer / no tile_set).
   - `viewport_to_cell(layer, viewport_pos, camera_xform, tile_size) ->
     Vector2i` — M1's camera lesson applies: compose
     Viewport.get_global_canvas_transform() with the layer's global
     transform, affine_inverse the click, divide by the LAYER's cell size
     (ground is 8x8; NOT base_map.tile_size), floor to Vector2i. Never use
     get_global_transform_with_canvas / canvas_transform (identity in the
     4.7 editor).
   - `mirror_cell(coords, map_size_px, tile_size) -> Vector2i` — the
     existing _get_mirrored_coords math, unit-owned after the port.
   - Walls guard: refuse painting when walls TileSet tile_size !=
     map.tile_size (validator would fail the map anyway).
2. **Plugin input**: third mode beside lane drawing and placement. Drag
   support: track last-painted cell per stroke so a drag paints a line
   (set_cell is idempotent per cell). Escape exits; dock toggle in sync.
3. **Painting** goes through TileMapLayer.set_cell on the real layer
   nodes, then the mirror helper writes the mirrored cell — mirroring
   stays explicit and testable rather than relying on the `changed`
   snapshot diff while an EditorPlugin paints.
4. **Dock UI**: three brush buttons (with tile-set previews later — start
   with names), a tile/atlas picker per brush (list atlas coords from the
   layer's TileSet; plain list first).
5. **Undo**: batch per stroke (begin/commit on press/release), one
   set_cell pair per cell in the stroke.
6. **Validator**: no new checks needed if the walls guard is honored;
   optionally add a warning when a painted walls cell sits outside map
   'size'.

## Engine facts carried from M1 (keep)

- Editor camera = scene SubViewport's global_canvas_transform; canvas_transform
  is identity in the editor; _forward_canvas_gui_input needs _handles.
- This 4.7.2 build's API quirks (learned via suite failures): TileSet source
  enumeration is get_source_count()/get_source_id(i) (no get_source_ids);
  PackedStringArray has no any(); Transform2D exposes no scale_basis/columns
  to GDScript; plain Node2D has no tile_size to set() (use the BaseMap).
- The interactive painting layer is user-in-the-loop verified (remote
  machine per the user's workflow); headless tests cover brush->layer
  resolution, cell math, mirror invariants, and the walls guard.
