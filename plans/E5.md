# E5 - Decide and implement lane-completion semantics

`WalkLane`'s desired state is `{lane_route_finished: true}`, but the fact is
**write-once**: only `change_lane()` and `Move.teleport()` clear it, and
`is_valid()` treats it as a hard gate. Its only runtime writer was
`WalkLane.on_arrive`, which set it on any empty-path arrival scene -- including
the terminal lane waypoint -- and thereby disabled the goal for the rest of the
unit's life. Units fought, killed, then stood still (upstream main never saw
this because arrival dispatch was dead).

That write was removed in the arrival-dispatch fix. Today the goal therefore
never completes, matching upstream main's behavior.

Decide one of:

- **(a) Keep it unreachable** and document that `WalkLane` is an ongoing
  behavior that never finishes (cheapest; current state).
- **(b) Make completion real**: give the fact a reset path and define what a
  finished unit does (hold position, guard the castle, return to a rally
  point). This is a gameplay decision.
- **(c) Remove the fact and the desired state**, turning `WalkLane` into an
  explicit patrol goal.

Whichever is chosen, the unit must not end at `goal=null` with no behavior.

`../ARCHITECTURE.md` "State facts".
