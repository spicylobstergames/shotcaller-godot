# C1 - Implement planner contradiction rejection

Port the approach from branch `planner-precondition-safety` (commits 27c0f21,
77b5d67), which implemented it against the pre-rename `prototype/` tree:
carry a `satisfied` dictionary of facts the branch requires AND that currently
hold (node or ancestor), and `continue` past an action whose preconditions
negate one. See IMPROVEMENT_PLAN.md Track C. Do not start without the owner's
go/no-go: it changes planning outcomes by design.

Detail and evidence: `../IMPROVEMENT_PLAN.md` (Track C).
