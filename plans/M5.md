# M5 - Editor follow-ups from windowed verification

## Goal

Close the two gaps found in the first windowed run of the M4 runtime editor:

1. **Tiles are always mirrored.** `map_editor.gd::_paint_at` writes the
   `TileBrush.mirrored_cell` twin of every painted cell with no way to opt
   out, so the editor can only author mirrored maps. Keep the M3 twin-cell
   contract as the default but give the author a per-session toggle.
2. **Nothing can be repositioned.** There is no way to move a building (the
   scaffold's castle/barrack/tower included) or an already-drawn lane point;
   the only edits are additive.

## Fixed decisions (do not re-litigate)

1. **Default stays ON for the mirror** — the M3/M4 acceptance ("mirrored twin
   cells") must keep passing, and shipping maps are symmetric. The toggle is
   per stroke, read live by the host; no signal plumbing needed.
2. **One move mode, not per-object modes.** A left-press grabs the NEAREST
   thing under the cursor within a 48px-pick radius (viewport-space, so the
   radius is zoom-stable): any `Line2D` point under `lanes/`, or any building
   under `buildings/<team>/`. Dragging moves it live, snapped to the 64px
   lane grid, matching how placement already snaps.
3. **Motion is position-only.** Moving a building does not change its name,
   team metadata, subtype, or directory; moving a lane point never inserts or
   deletes points. Cross-team moves and point deletion are out of scope (M6
   candidates).
4. **No plugin/dock changes.** The Godot-editor dock keeps its M1-M3
   behavior; the toggle and move mode are runtime-editor features.
5. **The new regression tests run synchronously** (the unit harness calls
   `run()` without awaits): instantiate `map_editor.tscn` under the test
   runner node, drive it through its UI signals and synthetic input events,
   exactly the shape the M4 scratch probe validated (then deleted).
6. **Undo/Redo stays `UndoRedo.new()` on the host**; a drag is one action:
   `add_undo_method` with the original position at grab, live position
   updates during motion, `add_do_method` with the final position at
   release/commit, `cancel_action()` when nothing changed. Undo during a drag
   first commits the drag at its current position.
7. **No GOAP/AI changes.** The editor still only writes maps; `pending_map`;
   WorldState stay as in M4.

## Implementation sketch

### `editor_ui.gd`

- Tiles section: after the `Paint tiles` toggle, a `Mirror paint` toggle
  button, `toggle_mode`, `button_pressed = true`, built inline (no host
  signal). Getter `mirror_enabled() -> bool` reads `button_pressed`.
- After the Buildings section: a `Move things` toggle emitting the new
  `move_mode_requested(active)` signal; tooltip covers grab/drag/release and
  Escape.
- `set_mode_active` and `_toggle_for` learn `"move"`.

### `map_editor.gd`

- `_paint_at`: read `ui.mirror_enabled()` once per event; skip the twin write
  (and keep the `mirrored != coords` guard) when off. `cell_size` and the
  walls guard are unchanged.
- Mode plumbing: `_set_mode("move")` via the new signal; `_unhandled_input`
  routes `move` events; Escape continues to commit and exit any mode.
- Drag state `var _drag := {}` with `{"kind": "lane"|"building", "node",
  "index", "orig"}`. `_commit_pending()` = `_commit_drag()` + the existing
  tile `_commit_stroke()`; every current call site switches to
  `_commit_pending()` (install map, save, validate, play, exit, undo/redo,
  mode switch, Escape) so history never holds a half-open drag.
- `_grab_move_target(viewport_pos)`: nearest candidate by viewport-space
  distance among lane points and buildings; refuse (empty `_drag`) when
  nothing is within the radius. Lane grabs surface the lane in the overlay so
  an author sees what they drag (the scaffold's `lanes` node is hidden by
  design).
- `_handle_move_input`: left press grabs, motion with
  `MOUSE_BUTTON_MASK_LEFT` held moves live, release commits; a motion whose
  button was released over the UI commits instead of dragging on (same rule
  as tile strokes).

## Out of scope

- Deleting buildings/lanes or points (right-click), renaming, duplicating.
- Moving buildings across team directories; lane re-subtyping on move.
- Marquee/multi-select; rotating; moving the fog or neutrals list.
- Dock/plugin parity for the new controls.
